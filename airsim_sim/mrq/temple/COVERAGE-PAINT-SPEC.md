# BUILD SPEC — HERCULES fleet cinematic: make the map-building unmistakable

## 1) Chosen design and why

**PRIMARY: COVERAGE PAINT (in-world) + SECONDARY: REVEAL RIBBONS, both driven by one shared clock.** The temple ground itself lights up with a glowing 1m tile grid exactly where the fleet's recorded 4m sensing discs swept (per-drone colors, pop-flash → frontier rim → settled fill), while each quad writes a glowing time-clipped path ribbon behind it — "space becoming known" plays full-frame on the ground the camera already films, using zero extra screen space, which is precisely the user's stated constraint and his own authored idiom (`/home/lucas/UE5/educationalVideos/slam/CONCEPT.md`: "the world paints itself in the robot's wake"; locked kungfu embedded-graphics pivot). It is honest (scorecard-exact cells, real first-seen times and first-toucher attribution, real FIS range=4.0m, ground-truth trajectories) and cheap (~9-12h): it lands inside `build_fleet_seq6.py`, which the temple agent already runs, so it rides the MRQ re-render that is in progress anyway — no new sim run, no canonical-run switch, no cross-run desync risk.

## 2) Implementation

**Data pipeline:** `meta_*.json` (t, ned) + spawn offsets → scorecard coverage cells (first_t, first_drone) → one 64x64 RGBA16 "first-seen-time" texture + 6 transform constants → decal material clocked by a single MPC scalar keyed in the LevelSequence. Trajectory keys → world-space ribbon OBJs with time baked as TEXCOORD0.u → same clock. **Integration point: MRQ sequence python (`build_fleet_seq6.py`), NOT ffmpeg.** The composite pipeline is untouched except one optional drawtext.

**Shared time domain (critical — fixes a clock mismatch between the two source designs as written):** normalize ALL times over `[t0_epoch - PRE, t1_epoch]` where `t0_epoch=1786733416.28`, `t1_epoch=1786733496.28` (from `/home/lucas/UE5/hercules-sim-big/mrq_work/temple/fleet_keys_temple.json`) and `PRE = t0 - min(first_t)` (~56s, computed by the bake). Texture R channel, ribbon u, and the CoverageTime clock all use this one domain, so tiles and ribbons can never disagree.
